The Governed Factory

One artifact plane, five gates, and two loops that learn — the design that implements all ten S7 feature priorities as genuinely running, deterministic mechanisms. No black box: every artifact is hashed, chained, traceable, and gated before it moves.

Four decisions that shape everything

Real, deterministic — not staged
The self-healing loop and the accuracy loop run for real on real run data. No LLM required; nothing in them is badged STAGED.
Three epics show the trend
EPIC-S7-001 plus two new synthetic epics (sponsor billing statements, member document e-consent), each with committed “actuals”. Error narrows epic over epic.
Minimal real downstream lane
A small synthetic target app in the repo. Patches apply for real, pytest runs red→green for real, release is a gated ledger event. Patch content pre-authored and labelled.
Artifact plane is the spine
All ten features are views or checks over one shared file plane — not ten separate subsystems.
01

The artifact plane

Every stage writes a JSON envelope to a deterministic path. The header carries a SHA-256 content hash and derived_from pointers at the upstream artifacts it was built from — which turns the plane into a provenance chain, makes staleness a hash comparison, and makes interrupted runs resumable.

artifacts/ ← gitignored, regenerated by running EPIC-S7-002/ assess/assessment.json design/dfd.json er.json stories/US-021.json … verify/verdict.json ← Gate 3 output build/ test/ docs/ release/ calibration/record.json ledger.jsonl ← append-only, hash-chained committed: crs/ (epics + actuals), rules/, skills/, target_app/, patches/
ledger.jsonl — the provenance ledger
One line per artifact event; each line carries the SHA-256 of the previous line. Editing history breaks the chain visibly — tamper-evident with zero infrastructure. A broken chain raises at load, naming the offending line.
meta.derived_from — the traceability matrix
Walk the pointers epic → design → story → task → test → release, in either direction. A defect traces backward in one lookup.
Staleness detection
Upstream hash no longer matches what downstream recorded? Downstream is stale, flagged in ledger and UI — and Gate 4 refuses release until it is regenerated. Regeneration is explicit (--refresh); it marks things stale rather than deleting them.

Honesty rule on G3
No LLM access yet, so Gate 3 is a rule-based verifier and is labelled exactly that in every surface — “rule-based checks today; second-model review when LLM access lands.” It is never presented as AI. The module boundary is where a second model drops in later, and only that module changes.
04

The accuracy loop — each epic makes the next one better

On epic completion, a calibration artifact records predicted vs. actual per stream and the run's error. Per-stream correction factors update (exponentially weighted), and the next epic's assessment applies them — recording both raw and corrected estimates, so the adjustment is visible, never hidden.

05

The self-healing loop — the factory fixes its own skills

The activity log records every stage outcome, including gate failures with their reasons. After each run, healing scans for recurring failure patterns and appends a versioned amendment to the responsible skill file — recorded in the ledger with the triggering log entries as derived_from.

The chain log entry → amendment → improved outcome is walkable in the ledger. This is change management running for real: impact recorded, amendment versioned, stability verified by the next run.

Contract, surfaces, tests

Contract — all additive
UserStory += purpose, impacts, feature_flag, rollback_plan · Task += task_type, patch_path · new: ArtifactMeta, Verdict, CalibrationRecord, SkillAmendment, DownstreamResult. Existing 60 tests stay green.
Surfaces
CLI: python -m s7_delivery.run <EPIC-ID> — full run, printed transcript, pytest-assertable. Console: three new panels — Ledger/Traceability, KPIs (accuracy + first-time-right), Factory (skills + amendment history). Both human gates stay.
Tests — one file per mechanism
Five gates block/unblock · envelope hashing · ledger tamper detection · staleness propagation · calibration narrows (asserted) · healing amendment lands and next run passes · downstream red→green. All offline, no API key.

What this delivers, feature by feature

  • Gated pipeline (5 gates) — G0–G4, enforced in the workflow layer
  • Four-layer architecture — rules / skills / workflows / orchestrator as directories
  • Story quality standards — contract fields enforced by G2
  • Provenance ledger — append-only, SHA-256 hash-chained
  • Factory activity log — session records in the plane, with durations
  • Independent review (G3) — verdict artifacts; labelled rule-based until LLM lands
  • Traceability matrix — derived_from pointers, walkable both ways
  • Change management — versioned, ledgered skill amendments
  • Completeness checks (G0–G2) — requirement→story mapping, AC coverage
  • Staleness detection — hash mismatch flags downstream; G4 refuses
  • + Accuracy loop — calibration narrows error each epic
  • + Self-healing loop — logs trigger skill amendments, next run proves them
