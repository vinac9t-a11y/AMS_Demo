# The governed factory — full implementation of the ten feature priorities

**Date:** 2026-08-06
**Status:** approved in brainstorming; awaiting implementation plan
**Source:** `docs/s7-feature-priorities.md` (all ten features), plus two additions
from the same conversation: skills updated by a self-healing process driven by
the activity log, and each processed epic increasing estimation accuracy.

## Decisions made during brainstorming

1. **Real, deterministic — not staged.** The self-healing loop and the accuracy
   loop are built as genuinely running mechanisms over real run data. No LLM is
   required for either; nothing in them is badged `STAGED`.
2. **Three epics demonstrate the accuracy trend.** EPIC-S7-001 plus two new
   synthetic MapleSure epics, each with a committed "actuals" file. Calibration
   error visibly narrows epic over epic (~±40% → ~±25% → ~±12%).
3. **Minimal real downstream lane.** A small synthetic target app lives in the
   repo; AGENTIC tasks apply pre-authored patches to it, pytest genuinely runs
   red→green, docs are generated, release is a gated ledger event. Execution is
   real; patch content is pre-authored and labelled as such until LLM access
   lands.
4. **Architecture: artifact plane as the spine (Approach A).** Every feature is
   a view or a check over a shared file plane — not ten separate subsystems.
   This matches the Adopt decisions already recorded in CLAUDE.md
   (§ Cache-efficient agent architecture, decision 5 and the second review).

## Honesty rules (restating CLAUDE.md, applied here)

- Gate 3 has no LLM yet, so it is a **rule-based verifier and is labelled
  exactly that** in every surface: "rule-based checks today; second-model
  review when LLM access lands." It is never presented as AI.
- Self-healing pattern detection is likewise rule-based (a table of
  failure-pattern → amendment templates) and says so in the UI. The mechanism
  (logs trigger amendments; amendments are versioned; the next run proves the
  fix) is fully real.
- Downstream patch content is pre-authored and labelled; the build/test/release
  execution around it is real.

## 1 · The artifact plane

Every stage writes a JSON artifact to a deterministic path:

```
artifacts/<epic-id>/<stage>/<artifact-id>.json
```

Each file is an **envelope**:

```json
{
  "meta": {
    "artifact_id": "…",
    "stage": "assess | design | stories | build | test | docs | release | …",
    "epic_id": "EPIC-S7-002",
    "producer": "pipeline | reviewer | verifier | healing",
    "provenance": "staged | human | live_ai | replayed_ai",
    "created_at": "ISO-8601",
    "content_hash": "sha256:…",          // hash of the body
    "derived_from": ["sha256:… <path>"], // upstream artifacts
    "verified": { "verdict": "…", "by": "…", "at": "…" }  // null until G3
  },
  "body": { /* the serialized dataclass */ }
}
```

- A stage whose valid output already exists on disk **skips** — interrupted
  runs resume for free (demo recovery, per hard rule 5).
- **Staleness detection:** if an upstream artifact's current hash no longer
  matches what a downstream artifact recorded in `derived_from`, the
  downstream artifact is stale. Stale items are flagged in the ledger and the
  UI, and Gate 4 refuses release until they are regenerated.
- Regeneration is explicit (`--refresh`); it marks downstream artifacts stale
  rather than deleting them.
- `artifacts/` is **gitignored** — it is runtime output, regenerated by running
  the pipeline, and the run is deterministic so a fresh clone reproduces it
  offline. What is committed: the epics and their actuals files in `crs/`, the
  rules and skills files, the target app, and the patches tasks apply.

**The provenance ledger** is `artifacts/ledger.jsonl` — append-only, one line
per artifact event. Each line carries the SHA-256 of the previous line
(hash-chained), so editing history breaks the chain visibly: tamper-evident
with zero infrastructure. A broken chain raises at load, naming the offending
line.

| Layer | Where | What |

| Skills | `s7_delivery/skills/<stage>.md` (+ `.history.jsonl`) | Per-stage instruction files, versioned; the thing self-healing amends |

## 3 · The five gates

```
epic → [G0 intake complete] → assess → design → [G1 HUMAN design review]
     → stories → [G2 story quality + AC coverage] → [G3 independent verify]
     → build → test → docs → [G4 HUMAN release approval] → release
```

- **G0 — intake completeness.** Epic parses; required sections present; open
  questions extracted.
- **G1 — human design review.** The existing gate, unchanged. Still blocks.
- **G2 — story quality (machine-checkable).** Every story has purpose,
  testable acceptance criteria, target component, impacts, feature flag,
  rollback plan; every AC is claimed by a task (`unsatisfied()` empty); no
  dangling dependencies.
- **G3 — independent verify.** A separate module re-checks stories against the
  epic and design and writes a **verdict artifact**; downstream stages refuse
  unverified input. Rule-based today, labelled as such; the module boundary is
  where a second model drops in later.
- **G4 — human release approval.** Same mechanics as G1. Refuses when anything
  in the chain is stale or unverified.

Gates fail loudly with **named reasons** — those reasons are what the healing
loop consumes. Gate blocking is enforced in the workflow layer so no surface
can route around it (same principle as today's `build_state`).

## 4 · The minimal real downstream lane

A small synthetic target app is committed at `target_app/maplesure_portal/` —
a tiny claims-submission module with a pytest suite.

Per AGENTIC task: **BUILD** applies the task's pre-authored patch → **TEST**
runs pytest for real (red before, green after; genuine output captured into
the artifact) → **DOCS** generates a change note from the diff → **RELEASE**
is a gated ledger event (G4). Non-AGENTIC tasks do not enter the lane and are
labelled hand-work, exactly as `Task.runs_in_downstream_lane` already encodes.

## 5 · The accuracy loop (calibration)

`s7_delivery/calibration.py`:

- On epic completion, write a **calibration artifact**: predicted vs. actual
  per stream, run-level MAPE, from the epic's committed actuals file in `crs/`.
- Update per-stream correction factors (exponentially weighted).
- The next epic's assessment applies current factors and records **both raw
  and corrected estimates** — the adjustment is visible, never hidden.

Three epics run in order produce a genuinely narrowing error curve. This is
the concrete form of the agreed estimates answer ("grounded in historical
delivery data") and feeds the estimation-accuracy KPI on the scorecard.

New epics: **EPIC-S7-002 — sponsor billing statements online** and
**EPIC-S7-003 — member document e-consent**, both at EPIC-S7-001's scale, each
with an actuals file committed beside it in `crs/`. Scenario framing must respect the open "one application or two?"
question — the new epics target the same MapleSure portal fiction and do not
resolve that question either way.

## 6 · The self-healing loop

`common/telemetry.py` is extended to write **session records into the plane**
(stage, outcome, duration, gate failures with reasons). `s7_delivery/healing.py`
scans the log after each run:

- A recurring failure pattern triggers a **versioned amendment** to the
  responsible skill file, appended to `skills/<stage>.md` and recorded in
  `skills/<stage>.history.jsonl` and the ledger, with the triggering log
  entries as `derived_from`.
- Demo beat: epic 1's stories fail G2 (no rollback plan) → healing writes
  amendment v2 to `skills/stories.md` → epic 2's stories pass G2 first try →
  **first-time-right rate** improves, attributably.
- The chain *log entry → amendment → improved outcome* is walkable in the
  ledger. This is feature 8 (change management) running for real: impact
  recorded, amendment versioned, stability verified by the next run.

## 8 · Surfaces

- **CLI:** `python -m s7_delivery.run <EPIC-ID>` (wrapped by
  `demo/run_epic.sh`) executes a full run and prints the transcript —
  agent-side surface, pytest-assertable.
- **Console:** three new panels over the same payload — **Ledger/Traceability**
  (walk any artifact back to its epic; stale flagged), **KPIs** (accuracy
  curve, first-time-right trend), **Factory** (skill files, amendment history,
  what triggered each). Both human gates remain in the console.

## 9 · Testing

One test file per mechanism, all offline, no API key:

- all five gates block and unblock correctly;
- envelope hashing and `derived_from` integrity;
- ledger chain tamper detection (edit a line → load raises);
- staleness propagation (change upstream → downstream flagged → G4 refuses);
- calibration narrows across the three epics (assert error decreases);
- healing writes the amendment and the next run passes;
- downstream lane red→green on the target app.
